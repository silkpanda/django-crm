{% extends "base.html" %} {% comment %} quote_detail.html: one quote, its lines, and the total. TEACHING NOTE — the total printed here is `{{ total }}`, computed in the view by core.quotes.quote_total from the lines in the database. It is not a stored field and it is not arithmetic done in this template, for the reason the quotes.py module note gives at length: a stored total is a second answer to a question that can be answered exactly, and it goes stale the moment a line is edited anywhere else. Summing the `rows` in this template would at least be self-consistent today — and would also be untestable, and would need the per-line amounts rounded before it added them, which is not the same total. Neither does any row here multiply through the `multiply` filter. Django's `multiply` opens with `int(value) * int(arg)`, and `int(Decimal("0.25"))` is 0, so a quarter hour of labour renders as $0.00 — quietly, on every fractional line. The amount is computed in Python and arrives as `row.amount`. The expired marker deliberately does NOT change the number. A quote that lapsed on the 30th still priced those laptops at $2,400; nobody has re-priced anything because the calendar moved. The page says the date has passed and leaves the arithmetic alone. The status buttons are POST forms, not links, because a link cannot change anything on the server and a quote's status is not a GET parameter. Only the moves `set_status` allows are offered — the view refuses the rest with a message, so offering every combination would be offering buttons that lie. Editing is offered even on an accepted quote, because the editor itself decides: it redirects with an explanation. Hiding it here would be a second copy of that rule, and the two would drift — the template would say the lines are editable while the view refused, or the reverse. {% endcomment %} {% load humanize %} {% block title %}Quote — {{ deal.name }}{% endblock %} {% block content %}
