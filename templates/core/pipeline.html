{% extends "base.html" %} {% comment %} pipeline.html: the kanban board, one column per stage, deals as cards. TEACHING NOTE: SortableJS (vendored into static/vendor, so no CDN) makes the cards draggable, and app.js saves the move. Each column shows its total and its weighted value: value times probability, summed. A $10,000 deal at 25% counts as $2,500 of likely revenue. pipeline_columns() in views.py adds these up in Python over the deals it already loaded for the cards, rather than asking the database a second time. Two details here that look like nothing and are everything: `data-can-edit` — the view's own permission answer, handed to the script. SortableJS ignores the HTML5 `draggable` attribute, so without this the board would be draggable for a read-only user and the server would have to refuse every move (PIPE-5). No "No deals" placeholder. It used to be rendered here, once, which meant it went stale the moment a card moved — the destination column showed a card AND the message for being empty. The empty state is now a CSS `:has()` rule keyed on the column body actually containing cards, so it cannot be wrong (PIPE-1). The `.sub` line says whose deals the columns hold, because the board's scope isn't obvious any more: a Rep always sees only their own, but an Admin can be looking at "Mine" and needs to know that's why the board looks thin. The same scope_switch partial puts the toggle in the head (QA-04). {% endcomment %} {% load humanize static %} {% block title %}Pipeline{% endblock %} {% block extra_head %}{% endblock %} {% block content %}
