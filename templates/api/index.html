TEACHING NOTE: `/api/` answers twice, from one view and one list of routes (`endpoint_docs()` in core/api.py). A browser sends `Accept: text/html,...` and gets this page; anything asking for JSON — or sending no Accept at all, which is curl, a script and the test client — gets the object. See `wants_html()` for why the test is the raw header rather than `request.accepts()`. Why bother with a page at all, when the JSON is right there? Because the people who need to know this API exists are Reps and the person who has to approve it, and neither of them is going to curl /api/ and read a JSON object to find out whether they can. It also stops the API root being a bare 404, which is what a GET of `/api` with no trailing slash looks like. The rows are a table and not a list of links to the endpoints themselves: the detail routes need a real pk, and printing `/api/companies/0/` would be a URL that 404s. Using it

There is no API key. A client signs in through {% url 'login' %}, keeps the session cookie, and sends it on every request. An anonymous request gets a 403 with a JSON body rather than the login page — a redirect to HTML is not an answer a client can use.

Lists are 50 to a page and take ?page=N. Asking for a page past the end returns 200 with an empty results list, so a client walking pages never has to treat the last one as a special case.

Money is a string. value and weighted_value are sent as decimal strings, not JSON numbers, because a JSON number is a double and $1,234,567.89 does not survive one. Parse them with a decimal type.

There is nothing to write to. Every route answers GET; anything else is a 405.
